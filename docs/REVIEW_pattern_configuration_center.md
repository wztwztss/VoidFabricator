# Void Fabricator — 27 实体样板槽与单机器 UI 复核

日期：2026-11-16  
复核对象：`TileVoidFabricator`、`VoidFabricatorGui`、`PatternPoolData`、`RecipePoolSlot`、`PatternEntry`、`PatternView`、`PatternGuiSession`、`PatternItemPanel`、`PatternItemGui`、AE 发布与智能倍增  
结论：旧“一张样板 27 池”复核结论全部废止；当前实现按“方块 27 张实体样板 + 每张一台机器 + 独立 325×309 GT 机壳 UI”复核。

## 1. 当前验收基准

1. 方块中部为 9×3 共 27 个实体样板槽。
2. 每张样板只放一台机器，独立打开自己的可视化配方 UI。
3. 普通 AE 合成终端正常看到并下单，普通 Crafting CPU 执行。
4. UI 有搜索、直接图标、逐行滚动/滑块、点击排除变暗、筛选相同、黑白名单和删除/恢复。
5. 流体显示真实流体纹理和数量，不显示桶。
6. 智能倍增、输出缓冲、执行只扣一次料保留。

## 2. 已成立的设计

- **实体边界**：Tile 保存 27 个 ItemStack 和对应 PatternPoolData；不再有方块机器槽。
- **单池边界**：PatternPoolData 运行态只保留一个 RecipePoolSlot，保存时只写一个 Pools 项；26 个空池不再隐藏在运行模型中。
- **发布边界**：逐张样板扫描并汇总，按 RecipeKey 去重，记录所有来源样板；普通 AE Provider 发布。
- **同步有界**：每次只同步一个主池摘要和当前 91 个可见条目（13×7），不同步整池全部图标。
- **滚动语义**：首行偏移由服务端维护，滚轮逐行、滑块映射 0–1；点击通过搜索后的匹配索引还原 globalIndex。
- **流体语义**：PatternEntry 保存真实 FluidStack，视图 NBT 和深拷贝均保留；UI 用 FluidDrawable，不再生成桶图标。
- **执行链未改坏**：普通 CPU 抽料，pushPattern 只消费交付输入，输出仍由持久化缓冲承接。

## 3. 本轮发现并修正的问题

### 3.1 把 27 池误放在一张样板内部

**问题**：上一版把用户参考图理解为“一张样板 27 台机器”，与最新三张图和文字相反。  
**修正**：27 格移到方块，每张实体样板只持有一台机器和自己的配方配置。

### 3.2 只隐藏旧 27 池而不是修改数据模型

**问题**：仅改 UI 会留下 26 个空池、重复扫描和错误迁移语义。  
**修正**：初始运行态只有一个主池；旧格式读取时才临时展开，迁移后裁剪，保存只写主池。

### 3.3 旧迁移重复条目并混入其他机器配方

**问题**：把主池条目也合并后再追加会重复；其他机器的条目可能进入当前主机器池。  
**修正**：保留 LegacyPools，选择主机器后清空并重扫，只恢复相同 RecipeKey 的启停状态，不追加其他机器条目。

### 3.4 槽组按 27 格一行注册

**问题**：MUI2 第二参数是每行槽数，不是总槽数。  
**修正**：方块样板槽组改为每行 9 格。

### 3.5 搜索/滚动后的服务端索引错位

**问题**：用旧页号或本地图标索引会操作相邻配方；删除/重扫后还可能落在空白尾部。  
**修正**：`requestedRow * 9 + localIndex` 映射到搜索匹配集合，再读取 globalIndex；同步前按当前行数钳制首行。

### 3.6 把分页网格误当作 TenkeiTech 滚动

**问题**：每页 27 条只能整页跳动，缺少参考图的滑块和逐行滚动。  
**修正**：13×7 可见窗口、服务端行偏移、DoubleSyncValue 滑块、列表/图标/滑块滚轮统一逐行；不再使用整页翻页。

### 3.7 流体被替换成桶

**问题**：旧 `buildEntry` 对流体主输出创建 `Items.bucket`，丢失真实流体显示语义。  
**修正**：保存 FluidStack 副本，UI 渲染 FluidDrawable，并显示数量与流体 Tooltip。

### 3.8 重复配方绕过单张样板的倍增关闭

**问题**：`ISmartDoublingMedium.isSmartDoublingEnabled()` 是方块级开关，一张启用样板可能让另一张已关闭的重复配方也倍增。  
**修正**：按 patternOwners 判断；任一来源关闭则倍率 1，启用时取所有来源最严格轮数。

### 3.9 空心圆角矩形日志洪水

**证据**：实例 `fml-client-latest.log` 在客户端和服务端大量重复 `Hollow rectangles currently can't have a corner radius`。  
**修正**：当前 UI 和旧编辑器中的 hollow+cornerRadius 组合移除，保留普通圆角实心背景和直角空心边框。

### 3.10 样板主手生命周期与秒关证据

**已确认**：MUI2 `PlayerInventoryGuiData.getUsedItemStack()` 直接按背包槽取栈，不是天然副本；`canPlayerInteractWithUI` 位于 ModularContainer。不能仅凭“客户端/服务端引用不同”认定首开秒关。  
**修正**：移除 `settings.canInteractWith` 校验；主手只做有效池样板检查，配置写回改为当前槽镜像。  
**边界**：右键秒关是否实机消除仍需用户用新 jar 复测；旧 AE selfRep 崩溃报告不作为证据。

### 3.11 关闭 UI 后机器配置被重置

**问题**：`PatternPoolData.save()` 只写回服务端打开 UI 时捕获的 `ItemStack` 引用；`PatternMachineHandler.insertItem` 写入新机器后，如果该引用不是当前主手槽对象，退出 UI 时槽内 NBT 没有更新，重开又按旧 NBT 构造数据。
**修正**：`PatternPoolData` 增加 `setOnSaved` / `persistNow`，每次 `save()` 后由 `PatternItemGui.mirrorToHand` 把完整 NBT 深拷贝到 `PlayerInventoryGuiData.getUsedItemStack()` 并 `setUsedItemStack`；关闭监听器再强制保存一次。该路径同时覆盖新机器写入和旧机器取出。

### 3.12 样板 UI 仍是自绘深色面板

**问题**：旧 `PatternItemPanel` 是 270×320、9×3、深色圆角自绘，和用户给的 TenkeiTech 模板输入总线完全不同。
**修正**：重写为 325×309、`GTGuiThemes.STANDARD`、13×7、电压标签（可整层启停）、搜索框、滑块、底部 GT 按钮和标准玩家背包；黑白名单、筛选相同、删除、恢复和倍增压缩到顶部同一行。静态布局已对齐 TenkeiTech 常量，但仍未实机截图验证。

## 4. 有意保留的语义选择

- 每张样板各有一套筛选、删除和倍增配置，不再是 27 池共享一套。
- “筛选相同”按主输出，忽略物品 NBT，不按完整 RecipeKey、配方类型或电压等级。
- 删除按完整 RecipeKey，重扫不补回；恢复删除清空该样板删除记录并重扫。
- 多张实体样板的相同 RecipeKey 在 AE 中去重发布，不显示多份。
- 重复配方的倍增采用所有来源中最严格设置，这是防绕过设计，不是每个来源独立执行。
- 旧 27 池样板采用有损迁移并保留 LegacyPools，不自动拆出其余机器样板。

## 5. 当前漏洞与未闭环风险

| 风险 | 影响 | 当前证据与缺口 |
| --- | --- | --- |
| 样板右键秒关 | 无法配置机器和配方 | 已移除 `settings.canInteractWith`；没有新实机结果，不能宣称根因闭环 |
| 关闭后 NBT 未写回 | 新机器被重置、取出机器仍残留 | 已加每次保存后的当前手槽镜像和关闭强制保存；未实机验证 |
| MUI2 2.3.94 滑块/搜索同步 | 滚动不回传、点击错位或断线 | 编译使用 2.3.92，实例为 2.3.94；真实往返需用户测试 |
| 325×309 UI | 面板裁切、背包错位、文本溢出 | 常量按 TenkeiTech 对齐并编译；未实机截图 |
| 27 槽 NBT 与自动化交互 | 重启丢样板、Shift 点击异常 | 保存/读取和槽组已编码；运行时未验证 |
| 27 张样板首次扫描 | 大量机器配方时卡顿 | 单槽异常隔离和只补建缺失扫描已编码；性能未实测 |
| 重复 RecipeKey 来源跟踪 | 错误倍增限制 | 源码按 owners 取最严格值；AE2-QoL 实际传入 details 身份需实机确认 |
| 普通 AE 发布与执行 | 缺样板、扣料或回注异常 | 原生 Provider/Medium 路径保留；未实机下单 |
| 大流体数量文本 | 图标文字过宽 | 图标只显示原始数字，Tooltip 显示完整 mB；极端数量需视觉复测 |
| 旧 27 池迁移 | 其余机器配置不能直接使用 | LegacyPools 保留，但自动拆分未实现；属于明示有损迁移 |
| 旧静态预览与 RenderPatternUi | 把旧双页面误认为当前 UI | 旧 PNG 不再作为当前设计证据；实机截图由用户测试产生 |

## 6. 静态验证边界

完整构建、语言和资源结果记录在 README。即使这些检查全部通过，也只证明源码可编译、资源可打包和静态引用一致，不证明 GUI 生命周期、AE 下单或游戏内布局通过。

旧 `docs/ui-preview-pattern-pools.png`、`docs/ui-preview-pattern-browser.png` 属于已否决的 27 池双页面，不能用于当前版本验收。当前静态布局预览为 `docs/ui-preview-pattern-ui-325x309.png`，由当前 `tools/RenderPatternUi.java` 生成，只证明布局与资源拼装，不是游戏实机截图。

## 7. 最小实测顺序

1. 手持空白样板普通右键，确认不秒关；放入一台机器，关闭并重开确认机器和配方保留；再取出机器，关闭并重开确认机器已清空。
2. 搜索、逐行滚动、拖滑块；在非首行执行左键、右键、删除和恢复。
3. 检查 325×309 GT 机壳、13×7 图标、电压标签、流体纹理/数量和玩家背包是否完整显示。
4. 在方块多个槽安装不同样板，验证 27 槽交互、保存重启和拆除掉落。
5. 普通 AE 终端确认所有去重样板可见、正常下单，普通 CPU 只扣一次料并正确回注。
6. 重复配方分别测试一张关闭倍增、不同最大轮数；验证最严格限制。
7. 验证断网、缓冲满、旧单池样板、旧 27 池样板和旧方块机器迁移。
